# 面试展示版 v1：电商搜索需求与点击效率诊断

## 状态与目标

面向电商搜索运营与数据运营岗位。数据分析、Spark对账和八页报告已完成；30条既有标题标注来源待作者确认，暂不作为人工证据。

## 数据与技术

- KuaiSearch-Lite 固定版本四份 JSONL，SHA-256 校验。555,553 次搜索、102,086 名去重用户、17,800,904 条商品曝光、680,790 次曝光内点击。
- Python 编排、DuckDB SQL 建立三层分析表与 39 项对账指标（13 项强制断言）；`python run.py` 全量重建。本机一次实测约 40.3 秒，不作为跨机器性能承诺。
- Spark 4.3 本地 `local[4]` 读取 Parquet 复算核心指标，与 DuckDB 一致。未处理官方 107 GB 全量，不做不公平的引擎速度比较。
- `dashboards/preview.html` 是网页版静态看板；`dashboards/静态看板.pptx` 是八页报告源文件，导出 `看板.pdf` 与 8 张截图；`dashboards/data/kuaisearch_dashboard.xlsx` 是数据源。相对时间索引不是日历日期。

## 三条可讲的发现

1. **曝光结构集中**：训练段 6.9% 的请求记录至少 100 条商品曝光，贡献 40.3% 的曝光。1–10 条与 100+ 条请求的商品点击率分别为 8.96% 和 2.19%；请求点击率方向相反。两种比率分母不同。
2. **分层比较差距幅度**：女装与训练总体的直接点击率差距约 0.78 个百分点；按列表条数分层后，差距约 0.25 个百分点。这是比较基准改变后的差距收窄，不认定原因。
3. **形成待核查清单**：124 个搜索词满足样本量门槛且低于同条数基准。Top 30 的描述性期望与实际相差约 6,416 次点击；这不是可回收点击或策略增量。优先人工检查“鞋子”“衣服”“手机壳”等词的商品与意图匹配。

## 运营动作与验证

先核实30条标注的来源与具体缺失字段，再选择一个动作。三项均按用户分流，以每用户首次合格搜索点击率为主指标；每臂4,324名用户是主指标规划下限，最终样本取护栏要求的最大值，线上预观察后锁定。配置、公式和开实验条件见[实验方案](experiment-design.md)。

## 不可越过的边界

- 召回列表顺序未证实为用户实际展示位；没有视口与滚动日志，不能用“首屏”“用户向下滚动”解释数据。
- `time_index` 不是实际日期；Lite 样本不能直接外推平台整体。
- 购买标签不是订单或 GMV。
- 现有 p/q 值把估计基准当固定真值，且先筛正差额再做 FDR；同一请求内商品曝光并非独立。暂不报告任何显著性结论，p/q仅为探索列，不参与本版筛选。
- 既有30条标注来源待作者确认，只覆盖高曝光样本，低点击原因待核查。
