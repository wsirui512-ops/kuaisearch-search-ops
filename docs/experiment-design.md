# 实验方案：把"诊断"变成"可验证动作"

> 说明：本项目没有线上实验数据，本文件交付的是**可执行方案**，不是实验结果。所有指标口径见 [指标口径](metrics.md)。

## 0. 通用原则

1. **一个实验只回答一个问题**，主指标只有一个，其余都是护栏。
2. **按搜索词/品类分层随机**，避免把流量结构变化当成方案效果。
3. 商品点击率必须**在同条数段内比较**（或直接以条数分层做分层随机），否则会被列表长度带偏。
4. 没有真实日期，样本量只能按"曝光/请求"计，不能换算成"跑几天"。上线前用实际流量换算周期。
5. 判读规则先写死：达到最小样本后看主指标；护栏出现显著恶化则停止，不看主指标。

## 1. 动作 A：泛品类词首屏收敛

**证据**：鞋子、衣服、外套、裤子、手机壳等词在"同条数基准"下仍低 0.7–2.2pp，且列表 34–68 条。

**假设**：泛品类词的用户意图宽，长列表让首屏被大量不相关商品占据；收窄首屏展示（如首屏 20 条精选 + 按细类目分组的"更多"）能提高单件点击率和请求点击率。

**设计**

| 项 | 内容 |
| --- | --- |
| 实验单元 | 搜索请求（按 query 分层随机） |
| 对象 | Top 10 泛品类词，单臂日均曝光约 3–5 万（用近期数据核对） |
| 对照 | 现有结果页 |
| 处理 | 首屏 20 条 + 细类目入口；其余商品折叠 |
| 主指标 | 同条数段商品点击率（点击商品 / 曝光商品） |
| 护栏 | 请求点击率、购买请求率、低曝光请求占比、商品覆盖量 |
| 最少样本 | 按 MDE 5%（相对）估算，每臂约 15 万曝光；MDE 8% 约 6 万曝光 |
| 周期 | 达到样本量即止（无日期字段，需用线上流量换算） |

**判读**：主指标相对提升 ≥5% 且护栏不显著恶化 → 扩大；主指标无变化但请求点击率上升 → 说明"更快找到"，可换主指标重做；护栏恶化 → 停止。

## 2. 动作 B：泛词拆成细意图入口

**证据**："鞋子"覆盖女鞋/男鞋/运动户外三个一级类目，请求点击率 45.5% 低于整体 53.2%，但用户仍会点。

**假设**：把宽泛词在结果页顶部提供"女鞋 / 男鞋 / 运动鞋 / 童鞋"入口，用户更快进入细分结果页，从而提升整体请求点击率与购买请求率。

| 项 | 内容 |
| --- | --- |
| 实验单元 | 搜索请求 |
| 对象 | 鞋子、衣服、外套、裤子、手机壳（5 个词） |
| 主指标 | 请求点击率 |
| 次指标 | 入口点击率、分支页商品点击率 |
| 护栏 | 购买请求率、低曝光请求占比 |
| 最少样本 | 每臂约 4,300 请求（MDE 3pp，基线 53%） |
| 风险 | 入口增加认知负担，可能降低点击；需看入口点击率 |

## 3. 动作 C：商品信息补全（手机壳/外套）

**证据**：手机壳 99.8% 曝光集中在手机/数码一级类目，缺口更可能在机型、材质、适配信息；外套类"春秋款"等季节属性与 query 的匹配无法结构化验证，但人工抽样可查。

**做法**：先做 100 条人工审阅（`outputs/review_sample.csv` 待生成/或直接用 `query_metrics` + 商品标题抽样），确认"标题缺少 query 关键属性"的比例，再决定是否值得做补全实验。

| 项 | 内容 |
| --- | --- |
| 实验单元 | 商品（按 item_id 随机） |
| 处理 | 补全标题/属性（机型、材质、季节、版型） |
| 主指标 | 目标商品的曝光点击率 |
| 护栏 | 类目购买率、商品覆盖量、审核成本 |
| 最少样本 | 每臂约 15 万曝光（同 A） |

## 4. 指标与陷阱对照表

| 陷阱 | 避免方式 |
| --- | --- |
| 用全局 CTR 比较不同列表长度的词 | 条数分层基准 |
| 用 p 值当效果大小 | 看 gap_pp、置信区间、业务量级 |
| 把购买标签当订单 | 只报购买请求率，不报转化率/GMV |
| 用平均各行 CTR | 一律 SUM(分子)/SUM(分母) 重算 |
| 把时间外测试当 A/B | 明确写"时间外方向复核" |
