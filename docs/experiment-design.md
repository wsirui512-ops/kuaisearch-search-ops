# 搜索运营实验预案

配置来源：`config/experiments.json`。样本公式由 `scripts/experiment_contract.py` 计算，报告、网页和第8页共用该配置。当前是规划方案，进入真实流量前须完成下表的开实验条件。

## 分流与指标

三项动作分开实验，按用户ID稳定哈希分流1:1；每用户只取实验期内第一次命中目标词的搜索作为合格搜索。主指标为**首次合格搜索点击率**：有商品点击的合格搜索数 / 合格用户数。入口点击不算商品点击。后续请求不计主指标，保留作探索。

商品ID不是本版随机单元；C在展示层按用户处理组补充经商家核实的属性，保持共享索引与召回不变。若只能全局修改商品标题，就改用商品集群随机，重新估算集群数，不沿用本方案样本量。

| 动作 | 证据与前置条件 | 处理 | Owner |
| --- | --- | --- | --- |
| A 结果分区 | 泛品类词存在分层差额；人工核查确认有可解释的细意图 | 同批商品分区，总数不变；记录渲染曝光 | 搜索运营+产品 |
| B 细意图入口 | 有可用的细分类目和稳定词包；上线前核查入口承接页 | 泛词顶部提供入口；监控分支返回 | 搜索运营+产品 |
| C 展示属性补全 | 人工确认缺失字段，商家核实属性真实 | 只在处理组展示补充属性，不直接改共享商品标题 | 商家运营+产品 |

召回列表位置不对应首屏，也没有滚动日志；分区与入口的价值是待验证假设。现有标题标注来源未确认，C尚不满足开实验条件。

## 样本量与停止规则

规划假设：p0=0.53，p1=0.56，双侧α=0.05、power=0.80，绝对MDE=3pp。

```
p_bar=(p0+p1)/2
n=ceil((z(1-alpha/2)*sqrt(2*p_bar*(1-p_bar))
       +z(power)*sqrt(p0*(1-p0)+p1*(1-p1)))^2/(p1-p0)^2)
```

计算结果：**主指标每臂 4,324 用户**，共8,648名合格用户。这是主指标下限，不能拿它代替护栏样本量。53%来自全请求口径，首次合格搜索基线须通过线上预观察期重估；若不符，重新锁定n。

主指标固定样本检验：双侧95%差值区间下界>0且所有护栏通过才扩大。3pp是设计灵敏度，不要求观察点估计必须达到3pp。每日不反复做成功显著性判定；样本满后还需覆盖事先登记的完整业务周期。

| 护栏 | 单位与非劣界（规划） | 上线前必须锁定 |
| --- | --- | --- |
| 首次合格搜索购买请求率 | 同用户首次请求，允许下滑不超过1pp | 单侧97.5%下界>-1pp；按预观察基线与80%功效另算n |
| 低曝光请求占比 | 首次合格请求曝光<5条，占比增幅不超过1pp | 单侧97.5%上界<+1pp；另算n |
| 商品覆盖 | 每1000名合格用户覆盖商品数，相对下降不超过5% | 用独立预观察数据按用户重采样估计方差，另算n与区间 |

最终样本取主指标与三个护栏要求的最大值；任一护栏未定样本或预观察不足就不启动。多个护栏要求全部通过，属于联合通过门槛。成本控制为搜索运营配置词包、产品实现分流与埋点、商家确认属性；先投入一个动作，不同时跑三项叠加。

安全停机：埋点缺失或分流比例异常先暂停；购买请求率相对对照下滑>2pp且持续两个完整日、或曝光<5条占比增加>3pp持续两个完整日时人工停止并排查。这是运维规则，不作为疗效统计检验。退出需记录停止原因与全部样本，不从中挑选显著结果。

## 开实验前检查

搜索运营提交目标词和问题证据；产品核对哈希分流、跨端身份与曝光事件；数据运营预观察首次合格请求基线并锁定各项n；商家运营确认C的属性真实性。周复盘检查执行与异常；达到锁定样本和业务周期后一次性读结论。样本内没有真实日期或线上处理组，不填写实验天数和增长结果。
