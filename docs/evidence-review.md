# 标题预筛与人工核查

`scripts/build_review.py`按Top10候选词各取曝光前10件商品，生成本地`outputs/review_table.csv`与公开`review_coverage_summary.csv`。二字覆盖率只比较字面片段，不是相关性分数；“衣服”的标题可能写卫衣或短袖。

## 已有记录的处理

30条本地标注按每词曝光第1、5、10名抽取，计数26/4/0，其中部分相关为鞋子1条、长尾词3条。原上传清单说明为工具预填建议，与“人工抽检完成”的说法冲突。本版将该汇总移回`outputs/spotcheck_summary.unverified.csv`，不作为公开人工结论。没有修改判断、理由或Y列，也不以Y列单独证明审阅来源。

## 作者如何完成核查（约20分钟）

打开`outputs/spotcheck_30.xlsx`，逐条核对标题能否支持查询意图。1=足以判断符合；0.5=相关但关键属性不足；0=明显不符。只看标题与辅助类目，不用价格、图片、销量。逐条填写真实理由和Y确认。生成器发现已有文件会保留，不会覆盖。

作者核实完全部30条后，自行创建本地`outputs/reviewer_confirmation.json`：

```json
{"reviewer":"实际审阅者姓名或署名","reviewed_at":"实际完成日期","personally_reviewed_all_30":true}
```

该文件必须由实际审阅者确认，不由脚本推测生成。之后运行`python scripts/apply_spotcheck.py`，生成公开聚合及本地报告段落；发布前将报告的待确认状态改为真实完成状态。

## 如何使用

每词只有3条、按高曝光取样，不能估全量相关率；没有负面样本不等于全量无错配。相同二级类目不证明同款或同质化。若发现缺机型或缺季节，记录具体字段与商品，再讨论属性补全；若问题不复现，停止对应动作。
