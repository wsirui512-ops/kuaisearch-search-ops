## 2. 分析模块（v2 口径）

### A. 需求结构：搜索词意图分类
- 规则 + 人工抽检（200 条）：品牌/店铺、品类+修饰、纯品类、属性/场景、无品类信号。
- 规则在 `config/intent_rules.csv`（四类信号：brand / attr / scene / category），可审计、可替换。
- 输出：各标签的请求量、曝光、请求点击率、购买请求率、平均展示条数、同条数残差。
- 用途：把"低点击"从"词的问题"细化为"意图承接的问题"；也是后续动作分类的依据。

### B. 流量效率：分层校准后的机会识别
- 主指标（业务可读）：搜索请求点击率、购买请求率。
- 诊断指标（可辩护）：`曝光条数分层后商品 CTR 残差 = 实际 CTR − 同条数段基准 CTR`。
- 位置信号：`impressed_item_ids` 有序，可做位置曲线；但需区分"位置效应"与"条数效应"（当前证据显示主要来自条数）。
- 统计：候选门槛（请求≥100、用户≥30、曝光≥1000）+ Wilson 区间或双比例检验 + FDR 控制。
- 输出：机会表 v2（含样本量、残差、置信区间、测试段方向）。

### C. 承接质量：query × 商品证据
- 对 Top 10 候选搜索词，抽样 10 条/词的商品：标题属性覆盖（型号/材质/风格词是否命中 query）、一级/二级类目分散度、品牌集中度。
- 相关性标注文件（46,422 对、46,325 个 query，绝大多数 1 对/query）只做**人工抽检佐证**，不做聚合分析（已核实"鞋子"0 对、"手机壳"1 对）。
- 输出：100 条人工审阅表 + 3 条"具体商品证据"。

### D. 辅助分析
- 年龄段：**标注"记录值可能不可靠"**（12–17 岁占 17.1% 请求、0–11 岁仍有请求），只作结构描述。
- 相对时间：20 个等宽区间（`time_index` 不可还原为日期/星期），仅看量级波动。
- train/test 为**时间切分**（1–936,724 / 936,726–965,265），表述为"时间外方向复核"。

## 4. 技术栈决策

| 技术 | 角色 | 决策 |
| --- | --- | --- |
| Python + DuckDB | 本地分析与建模主体（3GB 单机足够） | **保留**，作为主引擎 |
| Power BI | 展示层（JD 常列，加分） | **做**，产出 5 页 + PDF + 截图；`.pbix` 放 Release |
| ClickHouse | 服务层/加速层，做交叉校验与耗时对比 | **阻塞**：本机无 Docker/WSL2，计划见 [技术栈](tech-stack.md) |
| Spark | 大数据工程信号 | **不做主线**；仅当目标 JD 明确要求时，加一页"全量 107GB 的分片方案 + 本地小样本验证" |
| Tableau / Streamlit | 备选展示 | 不并行铺开，避免分散精力 |

> 关键判断：3GB 数据上 Spark 属于过度设计，面试容易被追问"为什么"；ClickHouse 能讲"分析 → 服务"的完整链路，落地成本低。
> 若本机没有 Docker：优先 Docker Desktop / WSL2；否则退化为 ClickHouse 单机二进制，仍可完成对账与耗时对比。

## 7. 风险清单

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `run.py` 先删库后连库，环境不可用时会毁库 | 681MB 分析库丢失 | P0 改为"临时库构建成功再替换" |
| 商品 CTR 被"展示条数"混淆 | 结论口径站不住 | 分层校准 + 请求级双指标 |
| 相关性文件覆盖极低 | "属性不匹配"假设无法量化 | 改为人工抽检；不做过度的相关性统计 |
| 零结果率为 0 | 护栏指标失效 | 换成低曝光请求占比 / 请求点击率 / 购买请求率 |
| `query_id` 依赖 DuckDB 排序，跨环境不稳定 | 看板不可解释 | 用稳定哈希 ID + 本地映射表 |
| 搜索词含敏感内容 | 发布风险 | 发布前人工扫描 + 打码 |
| 时间被相对编码 | 不能做时段运营 | 只用相对区间，标题明确写"相对时间" |
| 过度工程化 | 时间不够、面试讲不清 | 一切以"能被追问并答上"为准，砍掉不必要规模 |

## 9. 简历表述草稿（完成后按真实数字回填）

- 基于 55.5 万次真实电商搜索与 1780 万次商品曝光，搭建 Python + DuckDB 三层 SQL 管道（40 秒全量重建、自动对账），输出需求结构—流量效率—承接质量三层诊断。
- 发现"高频泛词 + 长结果列表"类需求的点击效率显著低于同长度基准（X 个搜索词、Y 万次曝光），并从商品标题属性覆盖与类目分散度给出承接证据。
- 将诊断结果转化为 3 条可执行搜索运营动作，配套主指标/护栏指标与最小样本量估算，形成可交付的 A/B 实验方案。
